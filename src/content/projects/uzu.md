## 它解决什么

很多团队不想为「本地模型」再维护一个 HTTP 服务，而是希望模型推理就在应用进程里。
uzu 提供的是库形态：Rust 侧几行代码拿到 `Engine`、按 id 下载模型、开 `ChatSession` 多轮对话；
它把模型配置统一起来，便于持续加新模型，并用可追踪的计算来核对是否与参考实现一致。
在 Apple 设备上它利用统一内存，主打「无网络延迟、数据不出机器、没有推理调用费」。

## 什么时候用它

- 做 macOS / iOS 应用想内置本地模型能力 → 直接依赖 crate，不必外挂服务。
- 团队是 Rust 技术栈，希望引擎跟着应用一起打包与发布。
- 需要多轮会话对象长期复用的场景（同一 session 可连续服务多次请求）。

## 上手难点

- 目前公开的能力与优化以 Apple（Metal / 统一内存）为主，其他平台支持情况需自行确认。
- 模型必须在它支持的清单内（官方有 local-models 列表），冷门架构需要自己加配置。
- 作为库集成，升级可能带来 API 变化；单模型常驻内存，加载多个模型要自己算预算。
